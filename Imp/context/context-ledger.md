# Context Ledger — What the operator should trust

**Created:** 2026-08-21
**Purpose:** Make project context auditable and easy for Atishay to correct. This file is intentionally separate from the operating goal so that new facts do not silently rewrite strategy.

## Status vocabulary

- **VERIFIED** — directly confirmed by Atishay or supported by a concrete record in the repo.
- **STATED / UNVERIFIED** — Atishay said it, but the underlying number/claim has not been independently checked.
- **INFERENCE** — a conclusion drawn from evidence; useful, but not a fact.
- **SUPERSEDED** — previously true/useful but replaced by newer evidence. Keep for history; do not use for current decisions.
- **CONFLICTED** — two sources disagree. Do not reconcile silently; ask or gather evidence.

## Source priority

1. Latest direct statement from Atishay in the current conversation.
2. Verified operational records in this repo.
3. Older conversation/context exports.
4. Model inference.

When sources conflict, preserve both claims with their dates/status until resolved.

## Important distinction

This ledger is **not** the operating goal. It is the audit layer above the goal. A new fact does not automatically change the strategy. First classify it, then decide whether the evidence is strong enough to update `goal.md` or another canonical file.

## Correction protocol

When Atishay says something is wrong:
1. Mark the old statement **SUPERSEDED** or **CONFLICTED** rather than deleting history.
2. Add the corrected statement with the date and source.
3. Update the canonical topic file if the fact belongs there.
4. Only then update strategy/goal files if the correction changes a decision.
5. Do not propagate an unverified number as fact.
